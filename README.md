# 直播预言竞猜系统（独立剥离版）

纯本地可跑的全栈实现，Node.js + Express + SQLite，无外部服务依赖。

## 启动

```bash
npm install
npm run seed    # 初始化管理员账号（admin / admin123）
npm start       # 启动服务，默认 http://localhost:3000
```

## 访问地址

- 观众端：http://localhost:3000/
- 管理后台：http://localhost:3000/admin.html （用 admin / admin123 登录）

## 这玩意儿是怎么跑起来的？（讲故事版）

你可以把整个系统想象成一家**餐厅**：

- **public/ 文件夹** = 餐厅的「菜单和装修」。浏览器打开后看到的所有按钮、卡片、进度条，都是这里面的 HTML/CSS/JS 画出来的。它们本身不会算数，只是"长得像那么回事"。
- **server.js** = 餐厅的「后厨 + 收银台」。你点了菜（按按钮下注），前台（前端 JS）把单子递给后厨，后厨查库存（数据库）、算钱（结算公式）、然后告诉你结果。
- **data/yuyan.db** = 餐厅的「账本」。所有用户余额、下注记录、流水都记在这里面，断电不丢。
- **lib/sse.js** = 餐厅的「广播喇叭」。后厨一旦改了彩池数字，立刻通过喇叭告诉所有正在看的顾客"彩池变了"，不用大家反复刷新页面。

**关键理解：为什么必须启动服务器才能用？**

如果你直接双击 `public/index.html` 用 `file://` 打开它，你会看到漂亮的界面，但一点"投入筹码"就报错——因为前台JS想找后厨（`/api/predictions/1/bet`），可后厨没开门（`npm start` 没跑）。

所以正确流程是：
1. `npm start` → 后厨开门，监听 3000 端口
2. 浏览器访问 `http://localhost:3000/` → 后厨把 `public/index.html` 这份菜单递给你
3. 你在页面上操作 → 前端JS通过 `fetch('/api/...')` 找后厨要数据
4. 后厨查 SQLite 账本、算完、返回 JSON
5. 前端拿到 JSON 重新渲染页面

## 每个文件是干什么的

```
yuyan/
├── package.json          # 项目清单：告诉 Node.js 装哪些依赖
├── server.js             # ★ 主入口：后厨。所有 API 路由、业务逻辑都在这
├── db.js                 # 账本结构：建了哪几张表、有什么字段
├── seed.js               # 初始化：创建第一个管理员账号 admin/admin123
│
├── lib/
│   ├── settlement.js     # 算账公式：floor(失败池 × 你的钱 / 胜方池)
│   └── sse.js            # 广播喇叭：维护当前所有打开页面的连接，统一推消息
│
├── public/               # 浏览器拿到的"菜单"（静态文件）
│   ├── index.html        # 观众端页面：预言卡片、下注弹窗、历史记录
│   ├── admin.html        # 管理后台：创建预言、封盘、结算、作废
│   ├── css/style.css     # 所有样式：颜色、圆角、进度条、手机适配
│   └── js/api.js         # 前端工具：封装 fetch、管理登录态、连 SSE
│
├── test/
│   └── smoke.js          # 自动化冒烟测试：模拟 1000 轮随机下注
│
└── data/
    └── yuyan.db          # SQLite 数据库文件（自动生成，删了会重建）
```

### 一次下注请求的完整旅程

```
你点"投入100筹码"
  → public/js/api.js 的 bet() 函数发 fetch POST /api/predictions/3/bet
  → server.js 收到请求，authRequired 中间件检查你登录没
  → 查 predictions 表：这个预言是不是还在投注中？
  → 查 users 表：你余额够不够？
  → 查 bets 表：你是不是已经投过了？（UNIQUE 索引兜底）
  → 开数据库事务：余额-100，冻结+100，写一条 bet 记录
  → lib/sse.js 广播"彩池更新"给所有在线观众
  → 返回最新的预言数据给前端
  → 前端重新渲染进度条和你的筹码余额
```

### 三种角色看到什么

| 角色 | 能做什么 | 入口 |
|---|---|---|
| 普通观众 | 看预言、下注、看自己历史 | index.html |
| 主播/管理员 | 创建预言、封盘、选答案结算、作废、置顶 | admin.html |
| 系统/后厨 | 冻结筹码、按公式分红、广播、记流水 | server.js（无界面） |

## 已实现功能

### 观众端
- 多条预言卡片并行展示，实时彩池进度条
- 倒计时（封盘时间）
- 自定义筹码下注（快捷 10/50/100/全部），二次确认
- 实时预估收益（前端两位小数展示，后端整数结算）
- 单用户单预言仅可下注一次
- 历史记录（猜对/猜错/进行中筛选）
- SSE 实时推送状态变更
- 手机端自适应

### 管理后台
- 创建预言（标题、A/B选项、封盘分钟数、上下限）
- 提前封盘
- 选 A/B 结算（自动按彩池比例分红）
- 作废（全额返还冻结筹码）
- 置顶切换

### 结算规则（严格按 PRD）
- 个人盈利 = floor(失败方总筹码 × 个人投注 / 获胜方总筹码)
- 到手 = 本金 + 盈利，余数平台回收
- 失败方=0：只返本金无分红
- 作废：全额解冻返还
- 所有筹码变动有流水日志（data/chip_logs）
